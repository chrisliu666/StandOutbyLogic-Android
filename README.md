# 独数一帜

这是一个浏览器端数独网页小游戏项目。

英文名：`Stand Out by Logic`

网页： https://chrisliu666.github.io/StandOutbyLogic/

## 当前状态

项目目前已经完成静态网页实现，可通过本地 HTTP 服务运行。另有单机离线版本。

2026-10-30 补充：项目主实现已转为 Android 原生应用（Kotlin + 自定义 View），详见「Android 原生版（2026-10-30 补充）」章节；Web / Electron 版保留为历史实现，文件不删除。

## 当前实现文件

- `index.html`：页面结构、棋盘、控制区、看板娘、对局记录。
- `styles.css`：清新古典风格、萌化二次元视觉、棋盘和按钮样式。
- `app.js`：数独题目加载、种子码、鼠标交互、确认、提示、失败、记录等核心逻辑。
- `assets/mascot-reference.svg`：基于用户提供图片风格制作的 Ada 头像资源。
- `dev-server.js`：本地静态开发服务器，默认端口 `5188`。
- `start-dev-server.cmd`：Windows 启动脚本，支持可选端口参数。
- `stop-dev-server.cmd`：Windows 关闭脚本，按端口结束本地服务。
- `start-dev-server.ps1`：PowerShell 启动脚本。

## 产品目标

构建一个轻量、流畅、适合鼠标操作的数独网页小游戏。整体体验以交互为重点，视觉风格要求清新、古典、耐看。

题库需要从公开的网上数独题库或兼容线上数据格式的公开数据源获取。正式实现时，需要在文档中记录题库来源、授权信息和更新方式。

## 已确认构想

- 题库方式：本地生成题库。
- 难度设置：需要分级。
- 二次元表现：需要看板娘。
- 数据保存：对局记录保存在当前浏览器本地。
- 设备优先级：以电脑端鼠标操作为主，移动端不是第一优先级。

## UI 方向

- 风格清新、古典。
- 棋盘布局安静、清晰、易读。
- 使用标准 `9x9` 数独棋盘。
- 每个 `3x3` 宫需要有更明显的视觉分隔。
- 棋盘周围避免过度装饰，重点突出填数字和高亮交互。
- 使用克制的颜色、细腻的边框和有质感的字体。
- 在清新古典的基础上加入适度萌化和二次元氛围，但不能影响数独棋盘的可读性和操作效率。
- 看板娘名字为 `Ada`，头像使用用户提供图片风格的图片资源，用于反馈、陪伴和氛围营造，但不能抢占棋盘主体。

## UI 控件

界面需要提供以下按钮：

- 新题目：切换到一道新的数独题。
- 确认：提交当前选中格子的临时数字，并和该格子的正确答案对比。
- 撤销：撤回上一步玩家操作。
- 恢复：恢复被撤销的玩家操作。
- 重置：清空当前题目的玩家填写内容，回到初始题面。
- 撤销重置：在执行重置后，允许恢复重置前的玩家填写状态。
- 提示：系统直接填入并显示当前格子或指定格子的正确数字。
- 一键完成：直接填入所有正确答案，并按成功通关结算。
- 再来一局：在失败后出现，用于快速开始一局新游戏。
- 数字状态：显示 `1` 到 `9` 每个数字是否已经填满。

按钮需要易识别、易点击，并和整体清新古典、萌化二次元风格保持一致。

## 页面操作说明

- 页面需要提供清晰、简洁的操作说明区域。
- 操作说明应覆盖左键单击、右键单击、滚轮、双击、长按、右键长按、确认、提示等核心玩法。
- 操作说明应放在不干扰棋盘的位置，优先作为右侧控制面板中的紧凑说明卡。
- 操作说明文案要短，便于玩家快速扫读。

## 萌化与二次元交互特效

- 数字变化、高亮相同数字、撤销、恢复、重置、新题目切换时，可以加入轻量动效。
- 动效应偏萌化、二次元，例如柔和弹跳、星光、小贴纸感装饰、轻微闪光或角色化反馈。
- 特效必须克制，不能遮挡棋盘数字，不能干扰玩家连续操作。
- 特效需要保持性能稳定，避免长时间动画或大量粒子导致页面卡顿。
- 如后续加入角色或看板娘元素，应服务于反馈和氛围，不应抢占棋盘主体。

## 核心交互

每个数独格子以鼠标操作为主：

- 鼠标双击：将当前格子填入 `1`。
- 鼠标左键单击：选中当前格子；如果格子已有数字，则高亮所有相同数字。
- 鼠标右键单击：当前格子数字 `-1`。
- 鼠标滚轮上滚：当前格子数字 `+1`。
- 鼠标滚轮下滚：当前格子数字 `-1`。
- 鼠标长按：清除当前格子。
- 鼠标右键长按：确认当前格子的临时数字。
- 鼠标单击某个格子：高亮显示所有相同数字。

数字范围使用 `0` 到 `9`。其中 `0` 表示空格，普通游戏界面中应显示为空白。

玩家通过鼠标调整出的数字默认为临时数字，只有点击“确认”按钮或对该格子执行鼠标右键长按后，才进入答案校验流程。

## 确认与失败机制

- 玩家填写的数字默认是临时数字。
- 点击“确认”按钮时，校验当前选中格子的临时数字。
- 对格子执行鼠标右键长按时，也校验该格子的临时数字。
- 校验时，将玩家临时数字和该格子的正确答案进行对比。
- 如果数字正确，该格通过并固定为已确认状态。
- 已确认正确的格子固定后，颜色应改为和题面给定数字一致。
- 如果数字错误，错误次数 `-1`。
- 每局共有 `3` 次错误机会。
- 错误次数扣完后，本局游戏失败。
- 游戏失败后，需要显示“再来一局”按钮。
- 已确认正确的格子应和临时数字有明确视觉区分。
- 题目给定数字不消耗确认次数，也不应参与玩家错误判定。

## 结算与对局记录

- 游戏需要记录每局结果。
- 成功通关时，记录成功状态、通关用时和种子码。
- 失败时，记录失败状态、失败用时和种子码。
- 对局记录需要在界面中可查看。
- 对局记录保存在当前浏览器本地。
- 对局记录中的种子码应方便玩家复制或重新输入，以便复现该局。
- 用时从本局开始后计时，到成功通关或失败时停止。
- 使用“再来一局”开始新游戏时，应生成并记录新的对局。

## 提示机制

- 每局提供 `3` 次提示机会。
- 使用提示时，系统直接填入并显示目标格子的正确数字。
- 被提示填入的格子应标记为系统提示数字，并区别于题目给定数字和玩家确认数字。
- 系统提示数字的颜色需要清晰、正确，不能和临时数字或高亮状态混淆。
- 提示次数用完后，应禁用或明确标识“提示”不可用。

## 种子码机制

- 每局随机生成一个种子码。
- 种子码需要在界面中展示，方便玩家记录或分享。
- 用户可以手动输入种子码，重复进入同一局游戏。
- 同一种子码应稳定复现相同题目、初始盘面和答案。
- 新题目按钮默认生成新的随机种子码；如果用户输入种子码，则按输入种子码加载对应题目。

## 题库与难度

- 题库采用联网加载公开数独题库的方式。
- 题库需要支持难度分级。
- 界面需要允许玩家选择难度。
- 难度至少需要覆盖基础分级；具体命名可在实现时确定，例如简单、普通、困难、专家。
- 题库来源、授权信息、接口或数据格式、失败兜底策略需要在实现后补充到文档。

## 当前题库来源与兜底策略

- 种子码保存到当前浏览器本地，便于复现。
- 用户手动输入未保存过的种子码时，使用项目内置的确定性数独生成逻辑生成同一局，保证种子码可复现。
- 当前难度通过挖空数量控制：简单、普通、困难、专家。

## 桌面版（Electron 单机版）

- 2026-08-17 起，项目新增桌面单机版，打包为 Windows 可执行文件（exe），不依赖浏览器。

- 桌面版新增构建命令见「开发」章节的「桌面版构建」小节。

## 玩法行为

- 题目给定数字需要和玩家填写数字有明显区分。
- 题目给定数字默认不允许误改，除非后续增加明确的编辑模式。
- 高亮状态应跟随当前点击或当前数字变化即时更新。
- 鼠标单击某个数字后，所有相同数字不仅要背景高亮，数字本身颜色也必须发生明显变化。
- 当前选中格子的同一行、同一列、同一九宫需要使用和主界面明显不同的颜色高亮，避免颜色过浅。
- 右键操作棋盘格时，应阻止浏览器默认右键菜单。
- 鼠标滚轮在棋盘格上调整数字时，应阻止页面滚动。
- 交互优先面向电脑端鼠标操作设计；移动端适配可以后续补充，但不作为当前第一优先级。

## 键盘导航（2026-10-20 补充）

- 焦点在棋盘上时，方向键按上下左右移动当前选中格，边界处不越界；移动后选中格同步获得焦点。
- 选中格位于最右列时按 `ArrowRight` 直接进入右侧控制面板，聚焦面板第一个按钮；面板中按 `ArrowLeft` 且左侧没有可移动按钮时回到棋盘选中格。
- 按 `T` 使用一次提示，效果与点击“提示”按钮一致。
- 尚未选中任何格子时，第一次按方向键从棋盘中心格开始。
- 焦点在右侧控制面板按钮上时，方向键按屏幕位置移动到相邻按钮（上/下/左/右就近选择）。
- 焦点在数字状态栏时，左右键切换数字项，`1` 到 `9` 直接填入选中格。
- `Enter` 在棋盘格上确认当前格；在按钮上触发按钮自身的点击（新题目、确认、清除、提示、撤销等）。
- `Esc` 把焦点从任意位置移回棋盘当前选中格，便于纯键盘操作往返。
- 方向键、数字键、`Enter`、`Delete`、`Backspace`、`Esc` 在种子码输入框和难度下拉框中不拦截。

## 键盘快捷键与清除按钮（2026-10-20 补充）

- 键盘 `Delete` 或 `Backspace`：清除当前选中格。
- 键盘 `Enter`：确认当前选中格的临时数字，效果与点击“确认”按钮一致。
- 右侧操作区在“确认”按钮右边新增“清除”按钮，点击清除当前选中格。
- 清除操作要求当前有选中格且该格可编辑；未选中时提示“请先选择一个格子”，题面、已确认、提示格提示“该格不可修改”。
- 清除操作会进入撤销栈，可用“撤销”恢复。
- 焦点在按钮上时按 `Enter` 交给按钮自身处理（例如在“新题目”按钮上按 `Enter` 仍触发新题目）；焦点在输入框、下拉框时不拦截键盘。

## 数字输入方式（2026-10-20 补充）

- 数字状态栏：`1` 到 `9` 的数字项可点击，点击后把该数字填入当前选中格。
- 键盘输入：按下主键盘或小键盘的 `1` 到 `9`，把该数字填入当前选中格。
- 两种方式都要求当前有选中格且该格可编辑；未选中时用弹层提示“请先选择一个格子”，题面、已确认、提示格不可修改。
- 在种子码输入框、难度下拉框中输入时不触发棋盘键盘输入。
- 新填入的数字仍是临时数字，需要“确认”或右键长按校验。

## 计时暂停（2026-10-20 补充）

- 网页版标签页切到后台、窗口被隐藏时，计时暂停；回到前台后从暂停处继续。
- 桌面版最小化窗口时遵循同一规则：最小化期间不计入通关用时。
- 暂停基于浏览器 `visibilitychange` 事件与 `document.hidden` 实现，暂停期间不累加用时。

## 题目唯一解与种子缓存（2026-10-20 补充）

- 挖空生成题目时，每挖一格都使用回溯求解器校验是否仍有唯一解；只在唯一解保留时确认挖空。
- 目标挖空数量：简单 `36`、普通 `44`、困难 `52`、专家 `58`。单次顺序挖空未达目标时，最多更换 3 次挖空顺序重试并取挖空最多的一次；专家难度极少数情况下会略少于 `58` 格。
- 种子缓存（`localStorage` 中的 `stand-out-by-logic.seeds`）最多保留 `60` 条，按最近使用时间淘汰最旧记录；写入超出存储配额时，先淘汰一半再重试，仍失败则清空缓存。
- 载入已保存的种子码时，采用该种子保存时的难度，并同步右侧难度选择器，避免对局记录标记错误难度。
- 对局进行中点击“重置”只清空玩家填数，保留错误次数与提示次数，计时继续。
- 对局结束后点击“重置”视为重新开始：恢复错误次数与提示次数，隐藏“再来一局”，并重新计时。“撤销重置”会连同结束状态与计时起点一起恢复。

## 棋盘数字对齐（2026-10-22 补充）

- 棋盘数字继续使用 Georgia，不更换字体。
- Georgia 默认渲染旧式数字（old-style figures）：`1`、`2` 只有小写字母高度，`3`、`4`、`5`、`7`、`9` 带下伸部，`6`、`8` 带上伸部，因此视觉上大小不一且未垂直居中。
- 渲染时把每个数字包进 `<span class="digit d1">` 到 `<span class="digit d9">`，按数字分别做垂直位移：`3`、`4`、`9` 上移 `0.168em`，`5`、`7` 上移 `0.18em`，`6`、`8` 上移 `0.005em`，`1`、`2` 上移 `0.105em`。
- `1`、`2` 额外加 `scaleY(1.333)`，把旧式数字的 x 高度拉伸到与其他数字一致，宽度不变。
- 位移使用 `em`，随棋盘字号（`clamp(24px, 5.2vw, 44px)`）等比缩放。
- 棋盘行高固定为 `grid-template-rows: repeat(9, 1fr)`，九行等分，避免边框宽度造成格高不一致。

## 操作说明卡片（2026-10-22 补充）

- 右侧“操作说明”改为可折叠卡片：标题栏常驻，点击标题栏展开或收起内容，箭头随状态旋转。
- 默认收起；仅首次打开网页或首次启动桌面版时自动展开一次，之后保持收起。
- 是否已自动展开记录在 `localStorage` 的 `stand-out-by-logic.guideSeen`。
- 展开/收起使用 `grid-template-rows: 1fr → 0fr` 过渡；收起时内容设置 `aria-hidden="true"` 与 `inert`，避免焦点进入。
- 标题栏是按钮，可用鼠标点击，也可用 `Enter`、空格或方向键聚焦后操作。

## 种子码行可见性（2026-10-22 补充）

- 问题：双栏布局下页面固定 `100vh` 且禁止滚动；棋盘每格是 `<button>`，继承全局 `min-height: 38px`，九行最小高度约 `456px`，棋盘高度无法随宽度缩小，把下方“种子码”输入行挤出可视区域。
- 修复：棋盘行改为 `repeat(9, minmax(0, 1fr))`，格子重置 `min-width: 0; min-height: 0`，棋盘始终保持 `1:1`。
- 数字字号由视口宽度改为棋盘容器单位 `clamp(14px, 6.8cqw, 44px)`，随棋盘实际宽度缩放；棋盘声明 `container-type: inline-size`。
- 常见视口（`1366×657`、`1280×600`、`1100×700`、`1024×640`）下种子码行均完整可见。
- 极矮窗口（高度小于 `480px` 且宽度大于 `1020px`）改为整页纵向滚动，棋盘固定 `360px` 宽，种子码可通过滚动访问。
- 窄屏（`≤1020px`）仍为单栏整页滚动，种子码位于棋盘与数字状态下方。

## Android 原生版（2026-10-30 补充）

自 2026-10-30 起，项目主实现改为 Android 原生应用；Web / Electron 版保留为历史实现，源文件不删除，也不参与 Android 构建。

- 技术栈：Kotlin + 自定义 View + XML 布局；零第三方运行时依赖，仅测试依赖 `junit:junit:4.13.2`。
- 包名 `com.standoutbylogic.sudoku`，应用名「独数一帜」，竖屏锁定，`minSdk 26` / `targetSdk 34` / `compileSdk 34`。
- 游戏规则与 Web 版完全一致：临时数字 → 确认的两步机制、3 次错误、3 次提示、唯一解校验、种子码、撤销/恢复、重置与撤销重置、计时暂停、本地对局记录。
- 生成器沿用 FNV-1a 哈希 + mulberry32 + 基底盘数字重映射 + 带内行列洗牌 + 唯一解挖空，同一种子码在同一难度下稳定复现同一题面。
- 题目生成在后台线程执行（单线程 `ExecutorService` + 代际令牌），避免专家难度生成时卡住界面。
- 存储：`SharedPreferences` 文件 `stand_out_by_logic`；种子最多 60 条（按最近使用淘汰），对局记录最多 20 条；写入失败时先减半重试，仍失败则清空（与 Web 策略一致）。

5. 数字键盘：`1`-`9` 一行等宽按钮，紧接 Ada 行；单击临时填入，双击填入并直接确认。
6. 主操作：确认 / 清除 / 提示 三个大按钮；对局结束（通关或失败）后出现「再来一局」。
7. 数字状态 1-9：显示 `n/9`，填满变金色；单击只高亮棋盘上该数字的格子（再次点击取消），不再填入数字；固定在屏幕最下方。

汉堡抽屉内容：

- 难度单选（简单 / 普通 / 困难 / 专家）。已有进度时切换难度会二次确认，切换后开始新题。
- 「更多操作」区常驻展开（不折叠）：当前种子、种子码输入与载入、复制种子（缩小版）与「振动」开关同行、新题目、撤销、恢复、重置、撤销重置、一键完成；内容超出屏幕时抽屉内可滚动。
- 对局记录：结果、难度、用时、日期、种子；点击某条记录会复制其种子并填入种子输入框；支持清空。

消息提示（正确、提示已填入、错误、已清除、种子码已复制等）显示在**棋盘中央**（而不是屏幕中央）：不透明纸色圆角框 + 描边，淡入缩放、约 1 秒后淡出；不拦截触摸，显示层级高于抽屉。

### 触控手势映射

| 手势 | 行为 |
|---|---|
| 单击格子 | 立即选中（不等待双击判定），高亮同行列宫与相同数字 |
| 上下滑动 | 以格为步进：上滑 +1、下滑 -1，`0` 与 `9` 循环 |
| 双击 | 确认当前格（敲锤定音） |
| 长按 500ms | 清除当前格 |
| 点击数字键盘 | 临时填入选中格；系统双击时限内再点同一数字 = 填入并直接确认 |
| 点击数字状态 1-9 | 高亮棋盘上该数字，再次点击取消高亮（不填数） |
| 点击棋盘外空白 | 取消选中 |

滑动只对可编辑格生效；单击任意格都会更新选中与高亮。

### 震动反馈

| 事件 | 实现 |
|---|---|
| 选中格子 | 两次急促脉冲 `[0,40,65,40]`（默认强度时序波形） |
| 填入/修改临时数字 | 同上 |
| 提示填入（自动填入正确答案） | 同上 |
| 确认正确 | 同上 |
| 确认错误 | 同上 |
| 数字 1-9 全部就位 | 同上 + 棋盘边框闪光 |

所有震动统一为确认正确/错误的手感：默认强度时序波形 → 系统触感 → 旧版单次震动，逐级回退。
设置抽屉「复制种子」旁有「振动」勾选开关，默认开启，状态持久化到 `SharedPreferences`；关闭后全部震动（含系统触感）静默。
Manifest 声明 `VIBRATE`（普通权限，无需运行时申请）；马达不可用时静默降级。

# Sudoku Web Game

This repository is for a browser-based Sudoku mini game.

## Status

The project is currently in the requirements and documentation stage.

## Product Goal

Build a lightweight Sudoku web game with a fresh classical visual style and highly polished mouse interactions.

The puzzle library should be sourced from publicly available online Sudoku puzzle data or generated from an online-compatible dataset format. When implementation begins, document the selected source, license, and update method.

## UI Direction

- Fresh and classical style.
- Calm, readable board layout.
- Clear 9x9 grid with stronger visual separation for each 3x3 box.
- Avoid clutter around the board so the interaction remains the focus.
- Use tasteful colors, subtle borders, and refined typography.

## Core Interaction

Each Sudoku cell supports mouse-first input:

- Double-click: set the selected cell value to `0`.
- Left-click: increase the cell value by `1`.
- Right-click: decrease the cell value by `1`.
- Mouse wheel up: increase the cell value by `1`.
- Mouse wheel down: decrease the cell value by `1`.
- Long press: clear the cell.
- Single click on a cell: highlight all cells with the same number.

Value changes should stay within the supported Sudoku range. The intended cycle is `0` through `9`, where `0` represents an empty cell.

## Expected Gameplay Behavior

- Given puzzle clues should be visually distinct from player-entered values.
- Given puzzle clues should not be accidentally editable unless an explicit edit mode is introduced.
- Highlighting should update immediately when the focused or clicked number changes.
- Empty cells with value `0` should be displayed as blank in the board UI unless a debug mode is added.
- Right-click interaction should prevent the browser context menu on board cells.
- Wheel interaction should prevent accidental page scrolling while the pointer is over the board.
